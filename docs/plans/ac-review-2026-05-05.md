# AC review — OPEN sprint-tracked issues vs quantrix v0.2.0 template — 2026-05-05

Reviews every OPEN sprint-tracked HoneyLLM issue (21 total) against the [`ac-template.md`](https://github.com/JimmyCapps/quantrix/blob/main/docs/ac-template.md) shipped with quantrix v0.2.0:

- Two explicit headings: `## Code AC (verified by /quantrix:quality from diff)` and `## Manual AC (verified by /quantrix:guide + /quantrix:quality via artifact)`.
- Manual items in the form `[manual] · <action> · expect <outcome> · verify via <surface-map key>`.
- Multi-angle (≥2 ACs total), bounded (≤5).
- Companion file at `docs/testing/manual-tests/<N.M>.md` for any issue with manual AC.

## Method

For each issue: assess existing AC against the template, identify the gap, propose **Code AC** and **Manual AC** drafts.

**You mark accept / edit / reject; a follow-on PR folds accepted drafts back into issue bodies + sprint files + manual-test companions.**

Surface-map keys cited are from `docs/agent-context/known-surfaces.md`. Where a useful key doesn't exist yet, the proposal cites the storage path or DOM selector directly with a note that the surfaces map should be extended.

## Top-level finding

The existing AC content is **mostly substantive** — most issues have 2–4 concrete bullets covering both the code change and a manual smoke. What's missing is **structural conformance**:

1. None use explicit `## Code AC` / `## Manual AC` headings (all use a single `## Acceptance Criteria` mixing modalities).
2. Manual gates don't use the `[manual] · ... · verify via <key>` shape, so `/quantrix:guide` cannot interpolate verification commands from the surfaces map → user has to invent the verify clause each time → drift.
3. Several issues have manual surfaces (popup behaviour, extension reload smoke, OS-level integration) where the manual AC is implicit ("manual smoke") rather than an enumerated artifact.
4. Three Sprint 4 DetermiLLM items (#244, #245, #246) plausibly need a Manual AC even though they're "mechanical wiring" — at minimum one `[manual] · reload extension and confirm Phase 2 baseline byte-identical via popup` to catch silent regressions.

The Sprint 1.3 (#232) flow-through proves why this matters: the issue had a Manual AC ("3 consecutive cache-cleared scans of bricklink.com → CLEAN") but did NOT cite a surface-map key for verification. The Haiku-authored fix passed the Code AC and the user-run manual gate at the time, but the same site is now flagging again — the AC didn't pin the cache-clear surface or the popup-verdict surface, so the verification ran a different path than current re-checks.

## Cross-cutting recommendations

### Surface-map extensions needed

To make the proposed `verify via <key>` clauses runnable, `docs/agent-context/known-surfaces.md` should add:

- `popup:accordion-<probe-id>` keys for each probe accordion (currently surfaces map names some implicitly).
- `popup:verdict` for the headline verdict surface.
- `popup:byok-settings`, `popup:chat-tab`, `popup:isolate-button`, `popup:agentic-tab`.
- `browser:task-manager` for memory-bound checks.
- `harness:state-query` (added by #227 itself).
- `service-worker:console` and `offscreen:console` as canonical inspection surfaces.

This is a separate ~30-min issue: "Extend surfaces map with manual-AC verify-via keys".

### Companion files to author

Each issue with a Manual AC needs `docs/testing/manual-tests/<N.M>.md` per the quantrix template. **17 of 21** issues will need one (USER-only items #14, #124, #129, #8 + most Claude items). `/quantrix:sprint <N.M>` authors the companion file at execution time, but having a stub-with-headings committed alongside the AC adoption would help the pre-flight gate.

### Multi-angle verification

Of the 21 issues, **13** currently have ≥2 ACs covering different angles (test gate + manual smoke OR test gate + regression baseline). **8** have ACs that all check the same axis (e.g. #244 all-code-test bullets, #246 pure CLI). For those 8, consider whether the work has a manual surface that should be added — or explicitly note "no manual surface, single-angle accepted" in the AC body.

### Sprint-file structure

The current sprint files use a freeform "Acceptance: ..." line per item. Recommend converting each `## Item N.M` block to:

```markdown
## Item N.M — <title> (#<issue>)

**Issue body AC** is the contract. Sprint kickoff prompt:

> <kickoff prompt>

**Companion:** `docs/testing/manual-tests/N.M.md` (if Manual AC present)
**Pre-flight notes:** <model match, repo state, pre-reqs>
```

This stops the sprint file and the issue body from drifting (issue body becomes the single source of AC truth; sprint file just points at it).
